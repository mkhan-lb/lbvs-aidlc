## Scope decision

Build the engineer workflow and artifact handoffs now, together with the plain-Markdown knowledge stores (`docs/adr/`, `docs/incidents/`, `docs/security/`, `docs/references/`, `docs/solutions/`) that the workflow writes into on confirmation, the `docs/platform/` pointer layer and default conventions. ## Current implementation — company AIDLC restructure

Repository to be published as `lbvs-aidlc`. Contract for this pass; completion is recorded in [verification](docs/VERIFICATION.md), not here.

- **Orchestrator.** `/aidlc [change-id]` starts or continues a change: it resolves the change ID, states the run's flow policy, proposes the `aidlc/<change-id>` worktree and asks; reads the project mode; for brownfield without a repository `CLAUDE.md`/conventions record invokes `aidlc-onboard`; then runs intent → design → plan → build → verify → review. Every stage ends with a summary and either an AskUserQuestion gate (**Proceed to \<next stage\>** / **Revise this stage** / **Stop here**) or an announced auto-advance permitted by the stated policy; only those two routes invoke the next skill via the Skill tool. After review, exactly **Fix findings (build)** / **Re-review at higher effort** / **Open PR (aidlc-ship)** / **Capture lesson (aidlc-learn)** / **Done**; the orchestrator drives the review loop below and hands off to `aidlc-ship` only on that choice.
- **Skill invocability.** `aidlc`, `aidlc-init`, `aidlc-intent`, `aidlc-design`, `aidlc-plan`, `aidlc-build`, `aidlc-verify`, `aidlc-review`, `aidlc-fix`, `aidlc-onboard`, `aidlc-learn`, `aidlc-ticket`, `aidlc-spike`, `aidlc-ship` are model- and user-invocable with a one-sentence outcome `description` and a `when_to_use` trigger line. Only `aidlc-handoff`, `aidlc-resume`, `aidlc-ideate` keep `disable-model-invocation: true`. No AIDLC skill uses `allowed-tools`, `hooks`, `model`, `agent` or `context` frontmatter. The package supplies 17 `aidlc*` commands.
- **Skill size.** Each `SKILL.md` body targets ≤ 5 KB (hard cap 7 KB). Repeated boilerplate preambles are replaced by one line: "Contract: docs/WORKFLOW.md. Paths are repository-root relative; bundled files are relative to this skill directory." Preserved contracts: exact-ID validation `^[a-z0-9]+(-[a-z0-9]+)*$`, post-write Read-back of saved artifacts, no invented approvals/metrics, plan mode returns proposals not saves, no commit/push/deploy without explicit authorisation, optional CE handoffs described by linking to the workflow guide.
- **Fix loop.** `/aidlc-fix <change-id>`: reproduce → failing test → authorised commit `test(<change-id>): reproduce <summary>` → marker `.aidlc/fix/<change-id>.json` `{"change_id", "protected": [...]}` → fix under `protect-tests.sh` (PreToolUse `Edit|Write|MultiEdit|NotebookEdit`, denies edits to protected paths while any marker exists) → test + `/verify` when a runtime exists → `changes/<change-id>/evidence.md` from `.claude/skills/aidlc-fix/templates/evidence.md` → delete marker → offer `/aidlc-learn`. `.aidlc/fix/` is gitignored.
- **Onboarding.** `.claude/agents/aidlc-repo-scout.md` is read-only (`Read, Glob, Grep`) and returns a structured conventions report. `/aidlc-onboard` delegates to it, asks Modernize / Stay legacy / Decide later, routes legacy to `inherit-legacy-style` and modernize to a `code-modernization` recommendation, proposes a ≤60-line repository `CLAUDE.md` with "Things Claude gets wrong here" and path-scoped `.claude/rules/` drafts (recommending `/init` with `CLAUDE_CODE_NEW_INIT=1` as the alternative), and writes them plus `.aidlc/mode` and `docs/onboarding.md` only on explicit confirmation.
- **Repository setup.** `/aidlc-init` (no argument; `when_to_use`: "set up aidlc", "initialise this repo", "adopt aidlc here", "brownfield setup", "init", "first time in this repository") is idempotent and report-first; each step ends with AskUserQuestion where it would write, every write is Read back, and it never installs plugins, changes settings, stores secrets, commits or pushes. Steps: (0) `doctor` → tool and MCP auth state, offer **Run doctor --install** / **Skip**; (1) `mode` → brownfield invokes `aidlc-onboard` via the Skill tool and keeps its scout report, greenfield offers **Adopt default conventions (conventions --apply)** and names the `docs/platform/README.md` app-template route when cloud delivery is needed; (2) `docs/platform/platform.md` still bracketed → offer to fill only what `.circleci/config.yml`, `deploy/`, `catalog-info.yaml`, `Taskfile.yml` reveal read-only, unknowns left bracketed; (3) MCP/CE: per server what needs auth (`atlassian` → `/mcp`; `github` → `GITHUB_PERSONAL_ACCESS_TOKEN`; `context7` optional) and whether `compound-engineering:*` is in the catalog, giving the install command; (4) `graphify` installed and `graphify-out/graph.json` absent → offer `/graphify .`; (5) **agent maker** — from the scout report (brownfield) or repository layout (greenfield), at most three candidates, each with name, description, tools, delegating stage and why `aidlc-verifier`, `aidlc-repo-scout`, `aidlc-design-reviewer`, `aidlc-threat-modeler`, `aidlc-test-critic` or the bundled Explore/Plan subagents do not already cover it; heuristics: ≥ 40 files or own glossary/docs → read-only `<repo>-<area>-scout`; documented multi-step test/build/verify procedure → Bash-capable `<repo>-checker` running only those commands; generated code with generator → read-only `<repo>-generated-guardian`; recurring documented procedure → a repository skill, not an agent; drafts from bundled `templates/agent.md` (angle-bracket placeholders only — the helper reserves `{{change_id}}`; sections Purpose, Inputs, Method, Output format, Boundaries, Provenance) written to `.claude/agents/<name>.md` only on confirmation, with the reminder that plugin agents cost startup context; alternatives named once — `/init` with `CLAUDE_CODE_NEW_INIT=1` and the official `skill-creator` / `plugin-dev` plugins; (6) `.gitignore` check for `.claude/worktrees/`, `.aidlc/fix/`, `.aidlc/current`, `.codegraph/`, offer to append; (7) summary Written / Recommended / Skipped, then exactly **Start a change (/aidlc)** / **Start from a ticket (/aidlc-ticket)** / **Done**.
- **Project mode.** `python3 scripts/aidlc.py mode` prints one line `AIDLC project mode: greenfield|brownfield — <reasons>`; `.aidlc/mode` overrides. `project-mode.sh` (SessionStart) injects it.
- **Shared instructions.** `AGENTS.md` is canonical; `CLAUDE.md` = `@AGENTS.md` + Claude-specific section; `.omp/AGENTS.md` imports `@../AGENTS.md`. The symlink and its export exception are removed. `.worktreeinclude` copies `.env` and `.claude/settings.local.json` into worktrees.
- **Worktree naming.** A `WorktreeCreate` hook (`.claude/hooks/worktree-create.sh` → `python3 scripts/aidlc.py worktree`) replaces Claude Code's default naming. `EnterWorktree` with the name `aidlc/<change-id>` yields the directory `.claude/worktrees/aidlc+<change-id>` on branch exactly `aidlc/<change-id>`, branched from local `HEAD`; a ticket key may prefix the ID (`aidlc/vs-1234-order-export`). Other names keep `worktree-<name>`. Because the hook replaces the default behaviour it performs the `.worktreeinclude` copy itself; an existing worktree directory is reused; a missing or unusable name fails the hook and therefore fails worktree creation. No host-side worktree marker is written, so Claude Code's worktree sweep does not manage these trees and removal is `git worktree remove`.
- **Change-ID resolution.** `python3 scripts/aidlc.py status` lists each `changes/<id>/` with the stage artifacts present, the stage reached, the next stage, the handoff count and a marker on the current change; `python3 scripts/aidlc.py current` prints `<change-id>\t<source>` and exits 1 when nothing resolves. Resolution order: branch name (`aidlc/<id>`, `aidlc+<id>`, `worktree-aidlc/<id>`, `worktree-aidlc+<id>`), then `.aidlc/current` (machine-local, gitignored), then the only change without `review.md`. Every ID-taking skill takes a valid `$ARGUMENTS` first, falls back to `current` and names the source, treats trailing prose as context behind a leading valid token, and otherwise asks — proposing a request-derived slug with a known ticket key as prefix, never inventing one and never creating `changes/<id>/` from an unresolved ID. `aidlc-ideate` keeps its topic ID with no fallback.
- **Flow policy.** The orchestrator states exactly one policy per run: `Flow policy: confirm each stage` (default, and the assumption when none is stated), `Flow policy: auto-advance when clear, stop before build`, or `Flow policy: auto-advance when clear, including build`. Each stage still summarises first. Auto-advance requires all of: an auto policy; the artifact saved and read back this run; no open questions, unresolved decisions or missing inputs; no failed check and no required check "not run"; no pending requested CE review; the next stage is not `aidlc-build` unless the policy includes build; and the next step is not a commit, push, PR, merge, publication or deployment. It then prints `Auto-advancing to <next stage> (policy: <policy>; no open questions, checks: <summary>)`, invokes the next stage with the bare ID and states that the engineer can interrupt. It always asks under confirm-each-stage, at `aidlc-review` (findings presented, post-review gate asked), when any condition is unmet, when implementation would start under "stop before build", and when a stage ended read-only or unsaved; `aidlc-fix` always asks its failing-test commit question and its closing gate; `aidlc-ship` always asks. Only under the including-build policy may the review loop's fix→verify→re-review cycles auto-continue, up to the three-cycle cap, announcing each hop. No gate is answered for the engineer and no unstated policy is claimed.
- **Helper and export.** Subcommands are `check`, `doctor` (`--install`), `mode`, `status`, `current`, `conventions` (`--apply`), `profile`, `worktree`, `package` and `new`: `check` validates the skills, agents, hooks, frontmatter rules, both vendor manifests and the knowledge-store indexes/templates; `doctor` reports `python3`/`git`/`claude`, the optional tools `graphify`, `codegraph`, `gh`, `omp`, and for each server in `.mcp.json` its authentication kind and whether the variable is set — `--install` runs the `uv`/`pipx`, `npm` or `brew` installer for each missing optional tool and never installs plugins or changes settings; `conventions` reports, per default file in `templates/conventions/`, whether the repository already owns that concern or a default is available, and `--apply` copies only the missing defaults, never overwriting; `profile` parses the header lines of `docs/repo-profile.md` and prints `profile: missing|fresh|stale (<n> manifest commits since <rev>)`; `package` exports them together with `.worktreeinclude`, `.mcp.json`, the knowledge-store indexes/templates, `docs/platform/`, `docs/references/`, `docs/glossary/`, `docs/playbooks/`, `templates/conventions/` and the vendor manifests; `mode`, `status`, `current` and `worktree` back the project-mode line, ID resolution and the worktree hook. Four hooks are registered (`check-package`, `project-mode`, `protect-tests`, `worktree-create`). Distribution remains repo-template export.
- **Project MCP.** `.mcp.json` declares `context7` (`https://mcp.context7.com/mcp`; anonymous, optional `CONTEXT7_API_KEY` whose value includes `Bearer `), `github` (`https://api.githubcopilot.com/mcp/`; `GITHUB_PERSONAL_ACCESS_TOKEN` required, `gh auth token`) and `atlassian` (`https://mcp.atlassian.com/v2/mcp`; OAuth 2.1 via `/mcp` on first use), with no credentials in the file. - **Stage wiring.** `aidlc-design` offers an ADR (architectural boundary, technology choice or contract) and a threat model (new external interface, data store, credential or trust boundary) by AskUserQuestion, never automatically; `aidlc-review` adds the Compliance check "architectural change without ADR" as a finding, not a blocker; `aidlc-fix` offers `docs/incidents/YYYY-MM-DD-<slug>.md` from the template linked from `evidence.md` when the symptom arrived through an alert/incident link, and a `docs/security/findings/` record for security defects. - **Traceability (from Kiro specs, ideas only).** `spec.md` acceptance criteria are EARS lines with stable IDs `R<n>.<m>` — `WHEN <event> THE <system> SHALL <response>`, `IF <condition> THEN THE <system> SHALL <response>`, `WHILE <state> THE <system> SHALL <response>`, ubiquitous `THE <system> SHALL <response>`, and for bug fixes `THE <system> SHALL CONTINUE TO <unchanged behaviour>`. `plan.md` tasks are numbered checkboxes `- [ ] T1.2 …` each ending `_Requirements: R1.1, R2.3_` plus `depends on: T1.1` where relevant; `aidlc-plan` checks every R-ID appears in ≥1 task. `aidlc-build` implements one task at a time in order (or the user's chosen task), runs that task's own check and ticks `[x]` in `plan.md` only after it passes, never ahead. `aidlc-verify` reports `R-ID | check | observed result | not run (reason)`. `evidence.md` gains the EARS triad Current / Expected / Unchanged that the reproduction and regression tests map to. Credit: [Kiro specs](https://kiro.dev/docs/specs/); Kiro's tooling (run-all waves, property generation, spec hooks) is not adopted.
- **Review loop.** Tiers map to the bundled `/code-review` effort argument: standard = `high` (default first pass), escalated = `xhigh` (re-review after a fix pass), maximum = `max`, cloud = `ultra` (multi-agent cloud review; costs more, needs the cloud feature) — the last two only when the engineer selects **Re-review at higher effort** or states it. Severity per REVIEW.md: **Important** vs **nit**; findings carry stable IDs (`R1`, `R2` …) across passes; `review.md` records each pass with tier, findings, disposition. Loop: review → Important findings → fix (`aidlc-build` with agreed IDs) → verify → re-review (escalated) … until zero Important findings or 3 fix cycles, then always stop and ask. Post-review gate options exactly: **Fix findings (build)**, **Re-review at higher effort**, **Open PR (aidlc-ship)**, **Capture lesson (aidlc-learn)**, **Done**. Under `Flow policy: auto-advance when clear, including build` the fix→verify→re-review cycles may auto-continue up to the cap, announcing each hop; the review pass always presents findings and the gate is always asked.
- **Ship.** `/aidlc-ship [change-id]` (model-invocable; `when_to_use`: "open a PR", "ship it", "ready for review", "create the pull request"; always asks). Preconditions from disk: latest `review.md` pass has zero open Important findings (else stop, point to the review loop); `evidence.md` or verify evidence present. Steps: `git status`/diff summary, branch `aidlc/<id>` or user-confirmed, refuse the default branch → AskUserQuestion exactly **Commit, push and open PR** / **Commit only** / **Stop here** → commit titled `VS-1234: <imperative title>` when the ID starts with a Jira key, else a Conventional Commit type, body why + `Change: <id>`, `changes/<id>/` committed with the code → push `aidlc/<id>` to `origin` only after the explicit choice, never the default branch, never force → `gh pr create --base <default branch> --title … --body-file <rendered template>` (github MCP when `gh` is absent) from bundled `templates/pr-body.md` (Summary, Ticket link, Spec/plan links, Evidence, Review, Knowledge records, Checklist) → read back the PR URL into `evidence.md`/`review.md` References. Never merge, approve, enable auto-merge or edit branch protection.
- **Context7 step.** Design, plan, build and fix resolve current docs for any library, framework, SDK or cloud API via the `context7` MCP (`resolve-library-id` → `query-docs`) or the `documentation-lookup` skill before relying on an API; cite the Context7 ID and the repository's pinned version in the artifact; when the lookup settled a real question, add/update the `docs/references/libraries.md` row in the same change. Context7 unavailable → say so and cite the official docs URL.
- **Platform and conventions.** `docs/platform/README.md` points at `Logicbroker/app-template` (greenfield route; `AGENT-SETUP.md` via authenticated `gh api`, raw links 404) and the `lb-pipelines/app-delivery-kit-vs@1` orb; `docs/platform/platform.md` is the per-repository facts template read by `aidlc-design`/`aidlc-plan`, which express deployment/observability/promotion changes as orb values/pipeline config; a new data store, queue or integration requires a `platform.md` entry and a threat-model offer. `templates/conventions/` holds `CONVENTIONS.md`, `.editorconfig`, `.pre-commit-config.yaml`, `ruff.toml`, `biome.json`; `aidlc-onboard` greenfield offers **Adopt default conventions (`python3 scripts/aidlc.py conventions --apply`)** and points to the platform README when cloud delivery is needed; brownfield runs `conventions` report-only and records existing tooling in the `CLAUDE.md` draft, never overwriting. `aidlc-build` runs the repository's pre-commit/lint before declaring a task done (none + greenfield → mention `conventions --apply`). Delivery execution stays deferred.
- **Agents.** Six under `.claude/agents/` with `.omp/agents/` counterparts (tools lowercase, `read-summarize: false`, deferring to the Claude definition): `aidlc-verifier` (Bash), `aidlc-repo-scout` (Read, Glob, Grep; conventions report and the `docs/repo-profile.md` draft), `aidlc-design-reviewer` (Read, Glob, Grep; adversarial review of `spec.md`/`plan.md` against intent, ADRs, `platform.md`, conventions; bounded pass list — requirements coverage & EARS quality, ADR consistency, platform fit, NFR gaps, missing threat model; verdict READY / NOT READY with numbered findings; ≤ 3 KB; adapted from awslabs/aidlc-workflows `core/agents/aidlc-architecture-reviewer-agent.md`, MIT-0; invoked by `aidlc-design` before the gate, verdict is a summary input, never approval), `aidlc-threat-modeler` (Read, Glob, Grep; STRIDE table for a named boundary from `docs/security/threat-model-template.md` with a do-not-flag list — test fixtures, accepted risks documented in `docs/security/`, framework-handled CSRF/escaping when verified; ≤ 3 KB; adapted from the AWS devsecops agent, MIT-0, and ECC security-reviewer false-positive list, MIT; invoked when a threat-model offer is accepted), `aidlc-test-critic` (Read, Glob, Grep; description ≤ 200 chars; inputs `spec.md` R-IDs, `plan.md` tasks, changed test files, `evidence.md` for fixes; passes — (1) coverage table `R-ID | test | asserts observable outcome? | gap`, (2) implementation-coupled or tautological tests and over-mocking, (3) missing failure/boundary/concurrency cases from EARS `IF`/`WHILE` lines, (4) flaky patterns — sleep, wall clock, network, order dependence, shared state, (5) for a fix: reproduction test present, protected during the fix, failing pre-fix per evidence; output `C<n>` findings with severity Important | nit and the smallest fix, plus a "Not examined" list; never edits, verdict advisory; ≤ 3 KB; idea adapted from affaan-m/ECC `agents/pr-test-analyzer.md`, MIT, covered by `docs/vendor/ecc/LICENSE`) and `aidlc-conventions-checker` (below). Wiring: `aidlc-verify` offers **Critique the tests (aidlc-test-critic)** / **Skip** once its R-ID map exists and reports the findings as input, not blockers; `aidlc-review` lists them in the context packet when a verify pass produced them; both skills stay ≤ 7168 bytes.
- **Repository profile.** `docs/repo-profile.md` in the adopting repository, drafted by `aidlc-repo-scout` from `.claude/skills/aidlc-onboard/templates/repo-profile.md` during `/aidlc-onboard` (directly or from `/aidlc-init` step 1; brownfield only) and written on confirmation with Read-back. - **Conventions checker.** `.claude/agents/aidlc-conventions-checker.md` (Read, Glob, Grep, Bash; description ≤ 200 chars; body ≤ 3 KB; `.omp/agents/` mirror). Inputs: change ID; `docs/repo-profile.md` (fallback `CLAUDE.md`, `CONVENTIONS.md`, `.pre-commit-config.yaml`, `.editorconfig`); `git diff <default-branch>...HEAD` plus uncommitted changes; `changes/<id>/spec.md` and `plan.md`; the glossary named in the profile.
