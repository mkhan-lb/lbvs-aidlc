# lbvs-aidlc plugin

Generated by `python3 scripts/build_plugin.py` from the repo-template sources; do not edit by hand.

Skills are namespaced `/lbvs-aidlc:<skill>` (`/lbvs-aidlc:lbvs-aidlc <change-id>` starts a change; `/lbvs-aidlc:lbvs-aidlc-init` sets a repository up). Agents: `lbvs-aidlc:lbvs-aidlc-conventions-checker`, `lbvs-aidlc:lbvs-aidlc-design-reviewer`, `lbvs-aidlc:lbvs-aidlc-repo-scout`, `lbvs-aidlc:lbvs-aidlc-test-critic`, `lbvs-aidlc:lbvs-aidlc-threat-modeler`, `lbvs-aidlc:lbvs-aidlc-verifier`. Hooks: project-mode and scaffold-version lines at session start, reproduction-test protection while `.aidlc/fix/*.json` exists in the project, artifact content-boundary lint on `changes/**` and `docs/solutions/**`, a confirmation gate on `git commit`/`git push`, and one-bare-ID argument checking on `/lbvs-aidlc*` commands. The helper is reachable as `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/aidlc.py" <subcommand>` or `bin/aidlc`; `conventions` uses the bundled `templates/conventions/`.

Oh My Pi loads the same plugin: `package.json` registers `omp/aidlc-guards.ts`, which supplies the mode line, test protection, artifact lint and the commit/push confirmation for omp sessions.

The plugin does not ship a `CLAUDE.md`; run `/lbvs-aidlc:lbvs-aidlc-onboard` or `/init` in the adopting repository. Shared workflow docs live under `docs/` inside the plugin and are referenced via `${CLAUDE_PLUGIN_ROOT}`.
