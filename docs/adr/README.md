# Architecture decision records

One file per decision that constrains future work: a boundary, a contract, a technology choice, a policy with teeth. Numbered `NNNN-short-title.md`; never renumber or delete — supersede. The `architecture-decision-records` skill writes here after you confirm; `aidlc-design` proposes an ADR when a spec makes such a choice, and `aidlc-review` flags architectural changes without one.

Sibling stores: [`../incidents/`](../incidents/README.md) for what went wrong and how it was recovered, [`../security/`](../security/README.md) for threat models and security findings, `docs/solutions/` for verified non-obvious lessons (`/aidlc-learn`). A recurring correction becomes a rule in `AGENTS.md` or `.claude/rules/`, not another record — knowledge is read at equal weight, so prune stale files rather than let them mislead.
