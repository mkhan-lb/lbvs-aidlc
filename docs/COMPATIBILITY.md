# Playbook and product compatibility

Checked against official documentation on 16 September 2026. This records documented capabilities, not a claim that an account or environment has them enabled. The article is preserved in [the source snapshot](sources/anthropic-playbook.md); source IDs and implementation state are in [coverage](COVERAGE.md).

The operational controls and services below are deferred reference research, not prerequisites for the [engineer workflow](WORKFLOW.md); [review options](../.claude/skills/lbvs-aidlc-review/references/review-options.md) lists the current alternatives. Future delivery will use CircleCI.

## Locally implemented mechanisms

- The `lbvs-aidlc` orchestrator and the stage, init, fix, onboard, learn, ticket, spike and ship skills are model-invocable and user-invocable with `when_to_use` triggers; only `lbvs-aidlc-handoff`, `lbvs-aidlc-resume` and `lbvs-aidlc-ideate` set `disable-model-invocation: true`. A stage advances on a user answer to an AskUserQuestion gate or, under a stated auto-advance flow policy, as an announced continuation through the Skill tool in the same session: prompt-level orchestration, not unattended jobs, background triggers or artifact-driven scheduling. The gate options, policy strings and fix-cycle cap are in [stage gates](WORKFLOW.md#stage-gates-and-the-flow-policy) and the [review loop](WORKFLOW.md#review-loop-and-escalation). [Skills reference](https://code.claude.com/docs/en/skills).
- `/lbvs-aidlc-init` is a skill, not a host feature. Every write (`platform.md`, `.gitignore` lines, a repository-specific `.claude/agents/<name>.md`) happens only after an AskUserQuestion and is read back. It does not install plugins (it prints the `claude plugin install …` command), authenticate MCP servers (it points at `/mcp`), run `/graphify` unasked or store secrets. The alternatives it names (`/init` with `CLAUDE_CODE_NEW_INIT=1`, the official `skill-creator` and `plugin-dev` plugins) are the host's own, not installed by this package. In plan or read-only mode the wizard returns proposals labelled **not saved**.
- The bundled `/code-review` skill takes an effort argument; the AIDLC review tiers are names for those values ([review loop](WORKFLOW.md#review-loop-and-escalation)). `ultra` is the multi-agent cloud review: it costs more, needs the cloud feature enabled for the account, and the skill says so before selecting it. Non-cloud `/code-review` treats trailing text as the target, so the wrapper cannot pass its packet as notes; coverage of artifacts and `REVIEW.md` is reported as confirmed or partial, never assumed. Finding IDs and severity are the wrapper's bookkeeping, not a provider feature.
- `/lbvs-aidlc-ship` uses `git` and `gh pr create` (or the github MCP when `gh` is absent) with the session's credentials and stores no tokens. Branch protection, required checks, CODEOWNERS and merge policy are repository settings that the skill neither reads as permission nor changes; a successful `gh pr create` proves only that a PR exists. What the skill refuses and never does ([shipping](WORKFLOW.md#shipping-a-reviewed-change)) is instruction text, not a Git hook or server-side rule.
- The `context7` MCP server supplies current library documentation through `resolve-library-id` and `query-docs`; anonymous use is rate-limited and `CONTEXT7_API_KEY` must carry the literal `Bearer ` prefix. When managed `deniedMcpServers` blocks the server or it is unavailable, the skills say so and cite the official documentation URL instead of falling back to training data silently ([rule](WORKFLOW.md#current-documentation-first)). `docs/references/libraries.md` is a hand-maintained log, not an MCP cache.
- The [official directory guide](https://code.claude.com/docs/en/claude-directory) permits a root `CLAUDE.md` and on-demand supporting files inside skill bundles; subagent definitions stay separate under `.claude/agents/`. `docs/WORKFLOW.md` is prose, not executable orchestration in `.claude/workflows/*.js`; authored `changes/<id>/` records are neither native settings nor runtime memory.
- Shared `.claude/settings.json` uses the official schema and registers eleven hook scripts in this repository ([project configuration](REFERENCE.md#project-configuration) lists them). Adopters receive seven of them (`protect-tests.sh`, `pr-guard.sh`, `artifact-guard.sh`, `argument-guard.sh`, `scaffold-check.sh`, `style-mode.sh`, `glossary-context.sh`) plus the helper `mode` line from the plugin's `hooks/hooks.json`. Glossary injection is one of these mechanisms: `glossary-context.sh` prints the company glossary index once at session start, and the same script runs under Oh My Pi through the guard extension. A deny is deterministic while its trigger exists, but hook startup, timeout and malformed-output failures fall through to normal permission flow, so hooks are guardrails, not security boundaries. A `WorktreeCreate` hook replaces the host's default creation, so its failure fails worktree creation. A hook never approves; `ask` still needs the engineer and is a refusal in headless runs. Path-scoped `.claude/rules/*.md` supply guidance, not enforcement. [Hooks](https://code.claude.com/docs/en/hooks) and [rules](https://code.claude.com/docs/en/memory).
- Project `.mcp.json` declares three remote HTTP servers and contains no credentials ([MCP servers](REFERENCE.md#mcp-servers)). Claude Code prompts once per project before connecting project-declared servers; managed `allowedMcpServers` and `deniedMcpServers` policy can still block them, and `doctor` reports only whether the variables are set, not that a connection works. Neither `.mcp.json` nor `.claude/settings.json` clears inherited user or managed settings, hooks or MCP connections, and neither adds tool grants, model or provider selection or telemetry; `codegraph install`, if a team runs it, adds its own MCP entry, `CLAUDE.md` section and permissions.
- Root `AGENTS.md` holds the canonical shared instructions; `CLAUDE.md` is `@AGENTS.md` plus a Claude-specific section, and `.omp/AGENTS.md` imports `@../AGENTS.md`. Claude resolves `@path` imports at launch; other hosts read `AGENTS.md` directly. No symlink is used. `python3 scripts/aidlc.py install` never mutates an existing `AGENTS.md`, `CLAUDE.md` or settings file and never touches global settings; adoption is an explicit reviewed merge ([scaffold](REFERENCE.md#plugins-and-the-repository-scaffold)). The earlier native Codex instruction-discovery smoke ran against the symlinked layout; no native Codex skill or hook parity is claimed and no `.agents/skills` mirror is supplied.
- `allowed-tools` is a temporary pre-approval grant, not a tool allowlist. The supplied skills do not use it to pretend to be read-only. [Skill permission controls](https://code.claude.com/docs/en/skills#pre-approve-tools-for-a-skill).
- A custom subagent's `tools` list restricts its available tools, but giving it Bash still permits side effects within the session's permissions. The verifier's instruction not to edit is not a sandbox. The four read-only agents (`lbvs-aidlc-repo-scout`, `lbvs-aidlc-design-reviewer`, `lbvs-aidlc-threat-modeler`, `lbvs-aidlc-test-critic`) list only Read, Glob and Grep, so they cannot write or run commands; their verdicts, tables and `C<n>` findings are text the calling skill summarises, never an approval or a control. `lbvs-aidlc-conventions-checker`, and any checker the `/lbvs-aidlc-init` agent maker drafts, has Bash so that `/lbvs-aidlc-ship` can rerun the repository's own lint, format and test commands; its limits ([pre-PR conventions check](WORKFLOW.md#pre-pr-conventions-check)) are prose the session's permissions still bound, not a sandbox, and its `K<n>` findings only change the shape of the ship question. `.omp/agents/` mirrors of all six defer to the Claude definitions with lowercase tool names because Oh My Pi reads its own agent format. [Subagent reference](https://code.claude.com/docs/en/sub-agents).
- Native plan mode is read-only and its native plan storage is not automatically the reviewed `changes/<id>/plan.md` artifact. The plan skill proposes content, then requires an authorised writable handoff to persist it ([saving a plan](WORKFLOW.md#saving-a-plan-before-implementation)). [Permission modes](https://code.claude.com/docs/en/permission-modes).
- The optional ECC import adds 26 discoverable reference and pattern skills and 12 explicit-invocation operational skills, plus the AIDLC-integrated `architecture-decision-records`. They inherit the current provider and normal permissions; imported frontmatter does not grant tools or install hooks. Provenance lives in the [ECC manifest](vendor/ecc/manifest.json) and the [anthropic-skills manifest](vendor/anthropic-skills/manifest.json) with its [NOTICE](vendor/anthropic-skills/NOTICE.md). The [MCP catalog](../mcp-configs/ecc.mcp-servers.example.json) is inactive reference material; `.mcp.json` is the live configuration.
- The EnterWorktree tool, `WorktreeCreate` hooks and `.worktreeinclude` are Claude Code features. Here the hook runs `python3 scripts/aidlc.py worktree`, which creates the directory and branch named in [worktrees](WORKFLOW.md#worktrees) from local `HEAD`, keeps `worktree-<name>` for other names and performs the `.worktreeinclude` copy itself, since the default behaviour no longer runs. No host-side worktree marker is written, so Claude Code's worktree sweep does not manage these trees. Without the tool or hook, the fallback in the same section applies and the copied local files must be recreated by hand. The helper subcommands are plain Python and run in any host; only the SessionStart injection and the hook wiring are Claude-specific.

The host loads a `native` surface from the file this package ships, with no code of ours in between. An `adapter-backed` surface reaches the host through code this package supplies for that host: the `.omp/hooks/pre/aidlc-guards.ts` extension for Oh My Pi (`omp/aidlc-guards.ts` in the plugin, where it also prepends the plugin's `bin/` to PATH so `aidlc` resolves in the bash tool) and the `.codex-plugin/plugin.json` manifest for Codex. An `instruction-backed` surface is text the host reads as instructions and may follow, with nothing that enforces it. A `reference-only` surface ships in the package and can be read or run by hand, but the host does not load it. An `unsupported` surface has no equivalent on that host. The suffix `(unverified)` means the declaration exists and no session on that host has exercised it.

## Conflicts and qualifications requiring care

| Source example or claim | Current documented qualification | Implementation treatment |
| --- | --- | --- |
| Auto mode / auto-accept terminology | `auto`, `acceptEdits`, `dontAsk` and `bypassPermissions` are distinct. Project/local `permissions.defaultMode: auto` is ignored; auto availability depends on provider, model and policy. | Do not install a misleading auto default or substitute bypass mode. User/managed selection and verified controls are prerequisites. |
| Nonempty `RELEASE_APPROVAL` in the sample hook | A local environment flag does not authenticate a release manager or bind a decision to a revision. Hook `ask` addresses the controlling session user, not a named external authority. | Query the selected authoritative release approval in the eventual integration; no copied sample authoriser is installed. |
| Hooks always enforce the gate | Some startup, timeout, exit-code and malformed-output failures continue normal permission flow. Async hooks cannot gate. Bash-only matchers omit edits and MCP calls. | Exercise failure and bypass scenarios; external permission and release boundaries must still hold when a hook fails. |
| Domain list blocks all egress | `sandbox.network.allowedDomains` alone pre-allows hosts; it is not a complete locked allowlist. Managed `allowManagedDomainsOnly` is a separate control. Shell sandbox controls do not cover every tool or process. | No blanket egress guarantee from the example JSON. Verify the actual network boundary. |
| No unsandboxed commands | `allowUnsandboxedCommands: false` removes the retry escape hatch, but `excludedCommands` remains an exception and can be widened locally; current docs state no managed-only lockdown for that array. | Do not promise an unbypassable endpoint sandbox. An administrator must establish the required execution boundary. |
| Marketplace/sideload settings guarantee every customization is approved | They do not alone disable normal home/project skills and agents. `strictPluginOnlyCustomization` is separate and can prevent this repo-local package from loading. | Choose a supported managed/approved distribution deliberately; repository assets are not automatically centrally enforced. |
| `allowManagedMcpServersOnly: true` means an MCP allowlist exists | It selects the managed allowlist; it does not populate `allowedMcpServers`. | Name and deploy the actual approved servers before claiming a restricted tool set. |
| `Bash(git *)` is a safe inner loop | This permits matching mutating Git operations too. Text matching is not a universal program identity or network boundary. | Scope actual allowed operations; do not copy broad grants as harmless defaults. |
| All hook decisions provide the needed audit automatically | OpenTelemetry must be enabled and collected; built-in events are not a signed named-approver or per-policy wait ledger. | Define explicit event and identity collection for the source's measures. |
| Sample minimum client version guarantees current hook behaviour | Current docs describe hook and auto fixes after the example's 2.1.193 floor. | Verify installed semantics; a version floor is not evidence that all controls work. |

All setting names in the article's managed JSON are documented; the issue is their scope and guarantees, not invented syntax. The article itself calls the JSON a starting point to tailor, not a configuration to copy.

## Service-specific prerequisites

### Deferred hosted PR review and the source's GitHub Actions example

The official `anthropics/claude-code-action@v1` supports the source's integration route; current inputs and security guidance must be followed. It needs a selected remote, runner, model credentials or federation and an authorised GitHub identity. A workflow file cannot install branch protection or nominate real code owners.

Do not use `pull_request_target` plus untrusted checkout to expose secrets to fork PRs. Restoring trusted Claude configuration does not make PR-controlled build scripts safe. The managed Code Review product is separate: its check is neutral, and `@claude review` requests another review rather than fixing comments. A GitHub action is an optional integration, not a prerequisite; fixes can use an ordinary build pass. No remote integration is configured here.

Sources: [GitHub Actions](https://code.claude.com/docs/en/github-actions), [official action contract](https://raw.githubusercontent.com/anthropics/claude-code-action/main/action.yml), [action security](https://raw.githubusercontent.com/anthropics/claude-code-action/main/docs/security.md), [managed Code Review](https://code.claude.com/docs/en/code-review).

### Hosted Claude Security

The article's recurring-scan play is the hosted service, not a local security-review prompt or plugin. Current official setup still requires Enterprise, web access, Extra Usage or funding, premium scan seats, an installed repository app and administrator enablement. Current product pages say Mythos 5.1 rather than the article's Mythos 5. The setup tutorial supports connected GitHub Enterprise Server as well as github.com and points to `/admin-settings/claude-security`, not the article's older path.

These pages establish no public API payload or signature contract. Do not invent a hosted scan client or claim a local plugin implements this integration. Entitlement, UI setup and scan evidence remain outstanding.

Sources: [product](https://claude.com/product/claude-security), [official setup](https://academy.claude.com/tutorials/getting-started-with-claude-security), [distinct local plugin](https://code.claude.com/docs/en/claude-security).

### Claude Tag

Current setup requires first-party Team or Enterprise access, Routines, funding, a compatible retention and encryption policy, Claude Owner and Slack administration. Teams is described as coming soon. Repository and operational investigation need explicit app grants or service credentials; the tagging user's personal connectors are not automatically channel access.

The administrator scopes channel credentials, and people in that covered channel can use them. Sandbox-local files are ephemeral, so the source's committed lessons need real durable publication. This package has configured no workspace or service credentials.

Sources: [Tag overview](https://claude.com/docs/claude-tag/overview), [setup](https://claude.com/docs/claude-tag/admins/setup-overview), [security and data](https://claude.com/docs/claude-tag/concepts/security-and-data).

## Decision

Preserve the playbook's control objectives and record differences rather than copying overclaimed guarantees. Local assets stay usable without asserting that external controls exist. The unresolved access and environment choices in [prerequisites](PREREQUISITES.md) block integrated verification, not the local workflow.
